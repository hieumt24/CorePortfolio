# CorePortfolio Project Context

## Purpose

CorePortfolio is a personal portfolio and cashflow application. It combines investment holdings, transactions, cash accounts, budgets, saving goals, DCA plans, rebalancing, analytics, and reports behind authenticated user-scoped APIs.

## Repository map

- `backend/src/CorePortfolio.Domain`: entities, enums, and accounting rules.
- `backend/src/CorePortfolio.Infrastructure`: EF Core `AppDbContext`, SQLite migrations, persistence services.
- `backend/src/CorePortfolio.API`: ASP.NET Core Minimal APIs organized by vertical feature slices; MediatR handlers live beside endpoints.
- `frontend/src`: React 19 + TypeScript + Vite application. Feature folders contain API clients, types, and components.
- `.agents/skills`: project-specific agent workflows.

## Backend conventions

- Entry point: `backend/src/CorePortfolio.API/Program.cs`.
- Map feature endpoints from `Program.cs`; use `RequireAuthorization()` for user data.
- Resolve identity through `ICurrentUserService.UserId` and filter every user-owned query.
- Use UTC dates and explicit VND/USD conversion through `ExchangeRateService`.
- CORS is configured by the exact `Cors:AllowedOrigins` allowlist and permits credentials for the refresh-token cookie. Wildcard Vercel preview origins are intentionally rejected; add every trusted preview origin explicitly and redeploy the API after changing this policy.
- Health checks: `/health/live` only verifies the process, while `/health/ready` (also exposed through `/health`) verifies database connectivity. Azure Linux should persist SQLite at `/home/data/CorePortfolio.db` or set `ConnectionStrings__DefaultConnection` explicitly.
- Database migration failures are logged as critical startup diagnostics but do not terminate the process; liveness remains reachable and readiness reports the database failure.
- Add entities to `AppDbContext`, configure relationships/indexes in `OnModelCreating`, and create an EF migration for schema changes.
- EF CLI resolves `AppDbContext` through `AppDbContextDesignTimeFactory`, so migration validation does not boot the API host or require JWT/provider configuration. The factory reads `ConnectionStrings__DefaultConnection` and otherwise uses a local design-time SQLite fallback; CI commands may continue overriding it with `dotnet ef ... --connection`.
- Preserve the vertical-slice + MediatR pattern; do not introduce MVC controllers.
- Sprint 0 data-integrity foundation: portfolio snapshots enforce one row per portfolio/day. Migration `AddSprintZeroDataIntegrity` removes legacy duplicate snapshots, normalizes legacy cash-account/ledger GUID casing once, and replaces the previous startup-time repair. API integration tests boot the real Minimal API against isolated in-memory SQLite databases and cover user isolation, transaction/ledger atomicity, snapshot uniqueness, and upgrading legacy data through the Sprint 0 migration.

## Frontend conventions

- Routes are registered in `frontend/src/app/App.tsx`.
- Shared navigation is `frontend/src/shared/components/Navbar.tsx`.
- HTTP calls use `frontend/src/shared/api/baseClient.ts`.
- Feature API clients and TypeScript contracts live under `frontend/src/features/*/api` and `types`.
- Visual language uses the premium glassmorphism tokens in `frontend/src/app/index.css`; preserve responsive states and explicit loading/error/empty UI.

## Current feature surface

- Admin Control Plane: the Admin Console now includes dedicated Audit Log, Operations, User Security, Market Data, Notification Management, Role & Permission, Data Integrity, and Backup/System pages. Backend contracts live under `Features/Admin/ControlPlane` as MediatR vertical slices and are exposed through `/api/admin/control-plane/*`.
- Admin audit and operations: audit events support server-side search, actor/entity/outcome/IP/date filters, correlation tracing, pagination, and frontend CSV export. Whitelisted manual operations can run Daily Snapshot or Market Price Refresh while updating `ProductionOperationsState` and writing an audit event.
- Admin user security: each JWT login now persists a `UserSession` keyed by the JWT `jti`. Token validation rejects revoked/expired sessions, throttles `LastSeenAt` updates, and Admin can inspect devices/IPs, view the security timeline, revoke one/all sessions, or change role. Access/role changes revoke existing sessions immediately.
- Admin RBAC: supported roles are `SuperAdmin`, `Admin`, `Operations`, `Support`, `MarketDataManager`, `Auditor`, and `User`. `AdminPermissionCatalog` defines least-privilege capabilities, authorization policies protect sensitive control-plane endpoints, and the Admin sidebar hides sections outside the current role's permissions.
- Admin market-data control: provider health aggregates Fresh/Stale/Error totals and exposes a bounded attention queue. Authorized operators can trigger the existing safe market-price refresh command; KBS remains keyless and prices remain absolute VND.
- Admin notifications: authorized roles can broadcast in-app System notifications to all active users or a selected role, with severity, optional deep link/expiry, per-user dedupe keys, recipient/read counts, and audit metadata.
- Admin data integrity: the console scans missing/stale market prices, unclassified ledger entries, orphan asset relations, portfolios without snapshots, and expired sessions. Repairs are whitelist-only; expired-session cleanup supports dry-run and audited idempotent execution.
- Admin recovery/configuration: the UI lists checksum-validated SQLite backups, creates online backups, performs confirmation-gated safety restore, and manages non-secret operational policy settings. `ScheduledBackupService` evaluates the persisted UTC schedule once per minute, runs at most once per UTC day, and reports status through the operations state. Runtime paths and secrets are never returned to the browser.
- Migration `AddAdminControlPlane` creates indexed `UserSessions`; it does not invalidate existing data. Existing JWTs issued before this migration must sign in again because they do not have a persisted session/JTI.

- Portfolio, asset, transaction, cashflow, cash account, analytics, report, watchlist, budget, saving goal, rebalancing, and DCA flows are present.
- Financial Health Center aggregate: `GET /api/dashboard/financial-health` and the dashboard integration.
- Recurring cashflow foundation: `RecurringCashflowRule` entity, persistence schema, and `/api/recurring-cashflows` list/create/toggle endpoints. Rule creation runs through a MediatR slice, accepts only supported currency/frequency/date values, normalizes calendar dates to UTC date-only storage, and returns not found for portfolios or private categories outside the authenticated user's ownership. Scheduler, idempotent occurrence generation, update/delete endpoints, and the management page remain to be completed.
- Notification Core: `Notification` now carries typed category/severity, entity/action metadata, expiry, read, and dismissal state. `NotificationPreference` stores user-scoped enablement and optional warning/critical thresholds; Budget defaults to 80%/100%. The MediatR notification slices expose paginated/filterable `GET /api/notifications`, `GET /api/notifications/unread-count`, read/read-all/dismiss commands, and preference GET/PUT endpoints. `NotificationWriter` is the idempotent write boundary: it honors preferences, requires a scoped dedupe key, handles uniqueness races, and returns Created/Duplicate/Suppressed outcomes. The Navbar uses the count endpoint and a five-item unread preview. Migration `AddNotificationCore` adds the schema; alert evaluators and the full Notification Center page remain for Sprint 2.
- User profile and security: `User` stores optional display name and email with a unique email index. Authenticated users can read/update only their own profile through `GET/PUT /api/profile` and rotate their password through `PUT /api/profile/password`, which verifies the current BCrypt hash. Registration now persists the existing frontend email field and requires an 8-character password. The `/profile` route provides responsive profile/password forms, while the N1b top Navbar places notification and conventional avatar menus on the right. Migration `AddUserProfile` adds the schema.
- Security Sprint 0: login no longer creates a default `admin/admin123` account. User passwords are persisted only as BCrypt hashes, and integration coverage locks this invariant. Portfolio updates and asset deletion now resolve resources through the authenticated owner and return not found for cross-user IDs. After deploying this change, operators must rotate existing administrator credentials and revoke their active sessions through the Admin User Security page.
- Security Sprint 1: `AdminPermissionCatalog` is the single source for least-privilege authorization policies. Admin endpoints now require explicit capabilities instead of the broad legacy `Admin` policy, sensitive MediatR mutations enforce the same capability at the handler pipeline boundary, and global cashflow-category mutations require `Settings.Manage`. Integration tests cover read-only Auditor access, MarketDataManager mutation, regular-user denial, global-category denial, and direct command dispatch.
- Security Sprint 2: access JWTs expire after exactly 60 minutes with zero validation clock skew and are held only in frontend memory. Login creates a seven-day opaque refresh token stored as a SHA-256 hash and delivered through an HttpOnly cookie; `/api/auth/refresh` rotates it on every use and revokes the full session when an old token is replayed. Refresh/logout endpoints require the `X-Requested-With: CorePortfolio` CSRF guard, CORS accepts only configured origins, and login/register/refresh/logout are rate limited by client IP. Logout, logout-all, password changes, role changes, and account-access changes revoke server-side sessions. Migration `AddRotatingRefreshTokens` adds the refresh-token chain; deploying it signs existing browser sessions out because legacy clients have no refresh cookie.
- Security 2FA Sprint 0: privileged-account TOTP foundation adds encrypted per-user authenticator secrets, hashed short-lived login/enrollment challenges, hashed single-use recovery codes, MFA-aware sessions/JWT `amr` claims, profile management APIs, attempt limits, IP rate limiting, and audit events. Protected login never creates a JWT, refresh cookie, or `UserSession` before the second factor succeeds. `Security:TwoFactor:EnforceForPrivilegedRoles` remains disabled by default until the Sprint 1 frontend enrollment/login UX is deployed; enabling it requires a Base64-encoded 32-byte `Security:TwoFactor:EncryptionKey`. Migration `AddAdminTwoFactorFoundation` is additive and leaves existing users unenrolled. Deployment, key-backup, and rollback guidance is in `docs/SECURITY_TWO_FACTOR.md`.
- Security 2FA Sprint 1: login now completes privileged enrollment and verification with QR/manual-key setup, authenticator or recovery-code entry, and a one-time recovery-code handoff. Profile Security supports voluntary setup, status, recovery-code rotation, and permitted disablement. Admin User Security exposes privileged enrollment coverage and per-user status; only SuperAdmin can perform confirmation-gated, audited break-glass reset, which revokes every target session. Conditional MFA authorization runs at both Admin HTTP policies and the MediatR admin-command boundary when enforcement is enabled, while a hosted cleanup removes retained expired/consumed challenges. The enforcement flag remains off by default and should be enabled only after the coverage panel reaches 100%. If the encryption key is absent while enforcement is off, status reports enrollment unavailable, the UI blocks setup, and the API returns HTTP 503 rather than leaking an unhandled configuration failure as HTTP 500. The shared frontend API client converts empty/generic HTTP failures into Vietnamese messages, while Login and Profile Security override 401/400/403/429/503 text for the active credential, setup, verification, recovery-code, or disable step instead of rendering raw strings such as `API Error: Unauthorized`.
- Credential leak prevention: `npm run check:secrets` scans tracked files for provider tokens, private keys, and non-empty credential settings without printing secret values. `.github/workflows/secret-scanning-ci.yml` runs the scanner on pushes and pull requests; rotation and history-rewrite guidance lives in `docs/SECURITY_CREDENTIAL_RESPONSE.md`.
- Market price foundation: CoinGecko supplies crypto, KBS supplies Vietnamese stocks/ETFs and indices, and the keyless `CorePortfolio.Fmarket` adapter supplies the complete public open-fund universe and latest NAV in absolute VND. `POST /api/admin/market-assets/sync-crypto` idempotently imports the configured Top 100 CoinGecko market-cap universe, while `sync-funds` imports every Fmarket fund and `sync-vn100` imports KBS VN100. Crypto prices refresh in cached batches every two hours by default through `MarketPrices__CryptoRefreshIntervalSeconds=7200`; provider failures preserve the last price as `Stale`. These public-data integrations are intended for this personal project; upstream terms and CoinGecko attribution requirements must be re-evaluated before commercial use.

- Admin operations console: `/admin/overview` aggregates platform, user, and market-data health; `/admin/users` provides searchable, paginated access management plus separate account and presence filters. `GET /api/admin/overview`, `GET /api/admin/users`, and `PUT /api/admin/users/{id}/access` are protected by the `Admin` authorization policy. Account access remains `User.IsActive`; successful login telemetry stores `LastLoginAt` and only the latest normalized IPv4/IPv6 address in `LastLoginIpAddress`. Authenticated JWT requests update `LastActivityAt` at most once per configured write interval, and Online is derived from the configured recent-activity window instead of persisted as a stale boolean. The access handler prevents self-demotion, self-lockout, and removal of the last active administrator; JWT validation still rechecks active state and role on every request. Migration `AddUserLoginTelemetry` adds the new fields/index. Production proxy and privacy guidance is in `docs/PRODUCTION_USER_ACTIVITY.md`.
- Admin navbar feature controls: `/admin/settings` can show or hide each user feature link in the shared navbar. `GET /api/settings/navigation/features` returns the authenticated-user configuration with enabled defaults, while existing admin-only setting updates persist each `NAV_*` toggle in `SystemSettings`. These controls affect navigation visibility only; routes and API authorization remain unchanged.
- Admin Market Assets: `/admin/market-assets` supports server-side search by symbol/name/external ID, category/source/status filters, sortable columns, and paginated results. `POST /api/admin/market-assets/sync-vn100` idempotently creates or updates the live VN100 universe in the Stock/Chứng khoán category and seeds the latest KBS reference price without issuing 100 quote requests. Existing assets are never deleted when index membership changes. The default order is symbol ascending (alphabetical), with deterministic ID tie-breaking.
- Portfolio Market Asset picker: `GET /api/portfolios/{portfolioId}/available-market-assets` is user-scoped, excludes assets already attached to that portfolio, supports category plus symbol/name search, ranks exact/prefix symbol matches first, and returns at most 50 compact options. The Add Asset modal uses this endpoint through a debounced searchable picker instead of loading a 1,000-item admin list.
- Telegram expense capture: `/chi [amount] "[category]" "[description]" [yyyy-MM-dd|dd/MM/yyyy]` records an expense for the earliest-created active Admin and that Admin's earliest-created portfolio. A successful command atomically creates the linked `CashflowRecord`, fiat withdrawal `Transaction`, and cash-ledger entry. `/cf` remains available for backward-compatible income/expense capture.
- Transaction tracking UX: `/transactions` now groups the global ledger into Crypto, Cổ phiếu, and CCQ/ETF tabs (with Vietnamese/English category matching), quick counts, category-aware add-transaction entry point, and an Edit action that reuses the existing user-scoped update endpoint. The add modal shows loading feedback while assets/categories are being resolved, a ledger-aligned payment/receipt total including fees, and a custom themed date-time picker. The existing user-scoped transaction API contract remains unchanged.
- Transaction asset auto-attach: the global `Record transaction` flow searches the full Market Asset catalog, including assets already attached to the selected user-owned portfolio. `POST /api/transactions` accepts either the existing portfolio `assetId` or a `marketAssetId`; when only the Market Asset is supplied, the handler creates or reuses the portfolio asset in the same database transaction as the transaction and cash-ledger entry, so validation failures roll back all three writes.
- Transaction filters and pagination: `/transactions` applies search, portfolio, transaction type, asset group, date range, amount range, ordering, and page size in the user-scoped backend query before pagination. The response includes asset-group facet counts, and export reuses the active filters.
- Vietnam time display: frontend timestamp rendering uses the shared `Asia/Ho_Chi_Minh` helpers in `frontend/src/shared/utils/dateTime.ts`; UTC API timestamps are converted to Vietnam time while date-only planning/report fields preserve their calendar date.
- Admin registration alerts: successful registration queues a deduplicated `System/Info` notification for every active Admin in the same database save as the new user. The notification deep-links to `/admin/users?search={username}` and contains no password or sensitive metadata.
- Vietnam market indices: authenticated `GET /api/market-indices?symbols=VNINDEX,VN30` reads KBS daily index data, accepting both numeric and string-encoded OHLC decimals used by the live provider. It returns current points plus session change/percentage, interprets KBS daily timestamps as Vietnam time, caches fresh quotes, preserves the last known quote as `Stale` on transient failures, and isolates hard upstream errors by symbol. The portfolio dashboard renders responsive VN-Index and VN30 cards with loading, retry, error, direction, source, and Vietnam-time states.
- Watchlist experience: `/watchlist` uses a stat-led signal board with search, category filters, target-distance context, price freshness, correct asset currency, responsive ledger rows, and explicit skeleton/error/empty states. The add flow supports symbol/name filtering and an optional target price. The watchlist DTO includes category currency plus price timestamp/status; no persistence migration is required.
- Transaction amount entry: the global Add Transaction modal accepts any two of quantity, unit price, and gross transaction total, then derives the third value. Users explicitly choose VND or USD; create/update handlers apply that requested currency to the linked cash-ledger account, while requests without a currency retain the asset-category fallback.
- Transaction file transfer: the `/transactions` ledger has a shared All/Crypto/Stock/Fund scope for import and export. It supports CSV, SpreadsheetML/binary XLS, and paginated PDF; PDF import understands official OKX and Binance Spot trading-history layouts. Binance fills preserve UTC+7 timestamps and normalize base-, quote-, or BNB-denominated fees into the transaction quote currency using the nearest BNB quote found in the report. Import opens a review step before any write, classifies ready/duplicate/invalid/out-of-scope rows, exposes missing Market Assets and portfolio assets, and lets Admins create and attach missing symbols inline. Duplicate fingerprints are skipped, assets and portfolios are resolved by ID/name, and writes continue through the existing validated transaction command.
- Transaction PDF export: generated reports use a landscape dashboard layout with scope/date metadata, KPI cards, readable transaction columns, type badges, page numbering, and embedded CorePortfolio data for lossless re-import.
- Transaction bulk deletion: authenticated users can delete all transactions or one asset group through `DELETE /api/transactions?assetGroup=All|Crypto|Stock|Fund`. The operation is user-scoped and atomic, removes linked cash-ledger entries and transaction-generated cashflows, and preserves portfolios, assets, and cash accounts.
- Transaction accounting and counts: Crypto sales whose acquisition history is missing are excluded from realized PnL until a tracked cost basis exists, preventing partial exchange imports from reporting sale proceeds as pure profit. Transaction group cards aggregate every API page (while respecting active type/date filters), rather than counting only the visible page.
- Portfolio valuation: `CurrentTotalValue` is the VND-converted market value of investment holdings only. Cash remains separately available through `CashBalances`; net-worth consumers add holdings and cash exactly once.
- Portfolio allocation report: `/portfolios/:id` shows VND-normalized holding percentages for Crypto, CCQ/ETF, and Stock, with Vietnamese/English category matching. Percentages use investment holdings as the denominator and exclude cash.
- Global report valuation: `/reports` calculates current value, profit/loss, category allocation, portfolio allocation, and historical report value from investment holdings only. Cash is excluded from these report figures while remaining available in snapshot `CashValue` and `NetAssetValue` fields for net-worth and performance consumers.
- Performance foundation: daily `PortfolioSnapshot` rows now persist holdings, converted cash, NAV, external flow, realized/unrealized P&L, income, fees, stale-price count, unclassified-flow count, and a quality status. `CashLedgerEntry.Classification` separates contributions/withdrawals from internal buy/sell/dividend/fee movements; migration `AddPerformanceDataModel` deterministically classifies and backfills legacy rows while retaining `TotalValue` as a compatibility NAV alias. The domain performance calculators cover flow-adjusted TWR, actual-date XIRR, absolute return, drawdown, monthly return, and monthly volatility with fixed-case unit tests.
- Performance API and UI: authenticated vertical slices expose `/api/performance/summary`, `/series`, `/drawdowns`, `/monthly-returns`, `/data-quality`, `/benchmarks`, and `/benchmark`. Portfolio/date/currency filters are user-scoped; current snapshot granularity supports `assetGroup=All` only. `/analytics/performance` is the responsive Performance Center with period/portfolio/currency filters, TWR/XIRR/P&L/drawdown KPIs, normalized benchmark comparison, NAV and drawdown charts, monthly heatmap, and explicit loading/error/empty/quality states.
- Performance benchmarks: `BenchmarkDefinition` optionally links an active `MarketAsset`; `BenchmarkPricePoint` stores exact daily closes and quality. Daily snapshots capture linked benchmark prices. Admin benchmark and price-point commands support configuration/backfill, while comparison normalizes both series to 100 on a common date and leaves missing benchmark dates as gaps instead of inventing prices. Migration `AddPerformanceBenchmarks` seeds inactive-data-ready VN-Index and Bitcoin definitions; they require a linked market asset or manually supplied history before comparisons become complete.
- Analytics decision-support Sprint 0: target allocations can only be saved as a complete 100% plan or cleared to 0%; duplicate, out-of-range, incomplete, and unknown-category inputs are rejected. `GET/POST /api/analytics/target-allocations` return plan status and actionability, while `GET /api/rebalancing/suggestions` returns an assessment wrapper and emits no adjustment options for incomplete/legacy-invalid targets or zero-value portfolios. Drift uses the configurable `Analytics:Rebalancing:TolerancePercentagePoints` band (5 percentage points by default) instead of the former 0.1% portfolio-value trigger. The Analytics UI exposes performance-data quality, preserves per-widget API errors with retry, labels tracked portfolio value accurately, and presents rebalancing as a manual consideration rather than a trade instruction. Execution-plan “apply” remains a manual reviewed-status marker and does not create transactions. No persistence migration is required.
- Analytics decision workspace Sprint 1: authenticated `GET /api/analytics/overview` composes the selected portfolio/date/currency performance summary and series, data quality, allocation, monthly cashflow, financial-health context, and goal/DCA summaries into one read model. The `/analytics` route now keeps period, portfolio, currency, and active workspace tab in the URL; presents an explicit data-trust banner, TWR/XIRR/drawdown decision KPIs, accessible NAV/external-flow chart summary, deterministic attention signals, and responsive Overview/Performance/Allocation/Cashflow workspaces. Financial health remains an explicitly labelled all-portfolio context when a single portfolio is selected. No persistence migration or predictive recommendation engine is introduced.
- Analytics explainable-insight Sprint 2: the pure domain `AnalyticsInsightEngine` evaluates deterministic, unit-tested rules for data quality, exceeded budgets, drawdown, target-allocation drift, repeated negative cashflow, at-risk saving goals, DCA cash coverage, and material TWR/XIRR divergence. `GET /api/analytics/overview` now embeds the ranked result and authenticated `GET /api/analytics/insights` exposes it independently with evidence, confidence, limitations, methodology version, scope, generated timestamp, and a non-advisory disclaimer. The Analytics insight rail supports category filters and expandable reasoning/evidence while retaining user-selected portfolio/date/currency scope. Rules do not predict prices, create notifications, mutate portfolios, or place trades; no persistence migration is required.
- Production hardening: Admin database backups use SQLite online backup with SHA-256 and `PRAGMA quick_check`; restore requires an exact confirmation, validates managed filenames, creates a safety backup, enters maintenance mode, and automatically restores the safety copy if post-restore validation fails. `/api/admin/audit-events` records actor/IP/correlation metadata for sensitive admin operations, while `/api/admin/operations` exposes maintenance and background-job status. Six high-contention entities use integer optimistic-concurrency tokens and global HTTP 409 handling. Migration `AddProductionHardening` adds audit storage and version columns. Readiness now fails during maintenance, CI applies all migrations to an empty SQLite database, and production readiness is a blocking deployment gate. See `docs/PRODUCTION_HARDENING.md`.

- Crypto rewards are recorded with `TransactionType.Earn`: they increase holding quantity at zero acquisition value (apart from an optional capitalized fee), create no purchase cash flow, and are rejected for non-crypto categories. Crypto imports tolerate sales above the tracked quantity, but exclude the unknown-basis portion from realized PnL; Stock and CCQ/ETF retain strict oversell validation. Accounting uses weighted-average cost, applies acquisitions before sales at the same timestamp, and reports realized, unrealized, and combined PnL separately. Portfolio category headers show combined PnL percentages for Stock, CCQ/ETF, Crypto, and any configured category/currency group; performance analytics includes realized PnL and closed positions.

## CI/CD

- `.github/workflows/backend-ci.yml` restores and builds the API project directly, runs domain and API integration tests, and verifies the EF snapshot.
- `.github/workflows/frontend-ci.yml` runs blocking `npm ci`, Vitest, and the production build; ESLint runs as an advisory step while legacy lint violations are migrated.
- `.github/workflows/text-encoding-ci.yml` validates source files as strict UTF-8 and rejects common mojibake markers across backend, frontend, documentation, workflows, and agent instructions.
- `.github/workflows/main_coreportfolio-api.yml` restores the API with the `linux-x64` runtime target, builds it, runs domain and API integration tests, publishes a self-contained Linux artifact, transfers it as a tar archive to preserve executable permissions, checks `/health/live` as a blocking smoke test, and logs `/health/ready` database status.
- Production deployment requires the Azure publish-profile secret and the API App Service CORS configuration described above. Vercel frontend deployment remains managed by Vercel; frontend CI is the merge gate.
- Frontend API routing uses an absolute `VITE_API_URL` when configured, falls back to the production Azure API URL in Vite production builds, and only uses same-origin `/api` during development. Relative production values such as `/api` are ignored to prevent Vercel SPA fallback responses. Vercel also proxies `/api/:path*` to Azure before its catch-all route, while the shared API client rejects any remaining HTML response with a configuration-specific error.

If an environment prevents backend restore/build, report the exact limitation; do not claim the backend is verified.
